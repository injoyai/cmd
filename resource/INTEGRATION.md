# 下载工具接入规则

本文件面向开发维护，约束 `i dl` / `i download` 的下载工具接入及相关安装行为。用户使用说明放在 [README.md](README.md)。后续接入、替换或删除下载工具时，应同时检查本文件、命令帮助和用户文档。

状态：三个 CLI 适配器和自动分流已实现。本文规定后续接入要求；各工具的平台依赖、参数范围和限制以用户说明为准。

## 1. 接入范围与职责

外部下载工具只接受 CLI 工具：必须能够通过命令行传入下载参数，在当前终端前台运行，并通过退出码报告成功或失败。只有图形界面、必须自动操作浏览器或依赖桌面窗口才能下载的工具，不纳入接入范围。

每个下载工具必须提供适配器，实现 `resource/download.go` 中现有的 `downloader` 接口：

```go
type downloader interface {
    Match(resource string) bool
    Dependencies(op *Task) ([]string, error)
    Download(ctx context.Context, op *Task) (filename string, exist bool, err error)
}
```

`Match` 负责自动识别；`Dependencies` 校验输入和参数、确定输出名称，返回所需工具的资源名；`Download` 负责参数映射和下载执行，通过 `op.tools` 使用统一入口已经解析的程序路径。适配器接入统一自动分流入口，通过接口类型检查。不得绕过接口，在 handler 中直接添加某个工具的下载流程，也不得以启动 GUI 代替下载实现。

`Dependencies` 不联网、不安装工具。单文件任务的最终目标已存在且不覆盖时返回空依赖，由 `DownloadFile` 直接复用；多文件任务不能因为输出目录已存在而跳过。无外部工具依赖的下载器返回 `nil, nil`。

每次接入先明确要解决的下载场景、输入类型、输出形式及与现有下载器的重叠。只有安装资源、没有实现接口和下载适配的工具，不算完成 `i dl` 接入。

沿用当前结构：

| 位置 | 职责 |
| --- | --- |
| `main.go`、`handler/handler_download.go` | 声明命令参数、传递配置、显示最终结果；两个下载命令行为一致 |
| `resource/config.go`、`resource/task.go` | 保存调用参数和本次任务状态；执行过程不修改调用方配置 |
| `resource/download.go` | 选择下载器、安装所需工具、统一重试和完成通知 |
| `resource/download_<工具或类型>.go` | 判断是否匹配、转换参数、执行下载、返回结果 |
| `resource/catalog*.go` | 定义工具资源、平台架构映射和发布包安装处理 |
| `internal/testutil/download.go` | 为外部工具提供测试子进程，验证实际调用参数和退出结果 |

复用 `downloader`、统一依赖解析、`DownloadFile` 和发布包安装函数。只有职责确实不同才增加处理函数；不为每个工具另建安装层、注册框架、配置系统或后台服务。

## 2. 命名与统一入口

下载统一使用 `i dl <资源>` 或 `i download <资源>`，由 `Match` 自动识别类型并选择实现。无需用户指定下载器名称；不新增工具选择参数、URL 前缀或独立下载子命令。

工具资源名仅用于安装和资源查询，不作为下载方式配置。当前命名如下：

| 安装资源名 | 实际命令 | 自动处理范围 |
| --- | --- | --- |
| `aria2` | `aria2c` | 磁力链接、本地种子任务 |
| `n-m3u8dl-re` | `N_m3u8DL-RE` | DASH、MSS 流媒体 |
| `gallery-dl` | `gallery-dl` | 已登记的图集、作者作品和相册路径 |

资源清单应同时索引规范资源名和实际本地命令名，Windows 使用对应 `.exe` 文件名。可执行文件名与资源名不同不构成两套实现。

适配器执行前先校验输入和参数，再查找或安装工具。模板和内置工具资源保留原安装语义。匹配范围重叠时明确登记优先级，不能靠用户增加选择参数解决冲突。

```shell
i dl 'magnet:?xt=urn:btih:...'
i dl './example.torrent' --proxy=""
i dl 'https://example.com/video.mpd'
i dl 'https://www.pixiv.net/users/123'
i install n-m3u8dl-re
```

## 3. 自动分流

`Match` 只判断输入，不联网、不安装程序、不写文件、不修改配置。下载器按照明确顺序选择第一个匹配项；错误处理不参与选择。

当前顺序为：模板 → 内置资源 → Telegram → RTSP/RTMP → 内置 m3u8 → N_m3u8DL-RE → gallery-dl → aria2 → 网站视频 → 普通 URL / 仓库资源。各类型按以下规则处理：

| 输入 | 自动处理约定 |
| --- | --- |
| 模板、内置资源、Telegram、RTSP/RTMP | 保留当前处理方式 |
| HTTP(S) `.m3u8` | 使用现有内置 m3u8 下载器 |
| HTTP(S) `.mpd`、`.ism/Manifest` | 交给 N_m3u8DL-RE，匹配放在网站视频之前 |
| 明确支持的图片站点 | 交给 gallery-dl，逐项登记站点和支持路径，并补匹配测试 |
| X/Twitter、Instagram、Reddit 等图文视频混合站点 | 保留当前 yt-dlp 分流 |
| `magnet:` | 交给 aria2 |
| 普通 HTTP(S) 文件链接 | 保留内置 HTTP 下载 |
| HTTP(S) `.torrent` 文件链接 | 只下载种子文件 |
| 本地 `.torrent` | 交给 aria2，执行前校验文件存在且为普通文件 |
| 其他资源名 | 保留仓库资源下载行为 |

匹配 URL 时解析协议、主机名和路径；路径扩展名判断忽略查询参数。站点判断使用完整域名或合法子域名边界，不用字符串包含判断。必须拒绝 `pixiv.net.evil.example` 一类伪匹配；不能根据工具宣称“支持很多网站”接管全部 URL。

新增自动匹配类型会改变既有命令行为，需要在用户文档中说明。不同工具支持同一地址不意味着增加失败回退链。

## 4. 工具查找与安装

统一入口在 `Dependencies` 成功后解析依赖：优先使用 PATH 中的程序，再复用 `i` 所在目录的程序，缺失时递归调用共用的内部下载流程，并补齐执行权限。适配器不得自行查找或安装依赖，不另建缓存目录，不自动修改 PATH。独立的 `MergeTS` 入口复用同一依赖解析函数。

依赖必须是资源清单中已登记的名称；别名按同一个资源识别。当前递归链检测循环依赖，同次任务共享已解析的程序路径，避免不同分支重复安装相同依赖。未知依赖和循环依赖直接报错，不回落到普通仓库下载。

依赖子任务只继承代理地址及忽略规则，安装目录固定为 `i` 所在目录，不继承业务任务的输出名称、覆盖、并发、重试和通知设置。递归下载不单独重试、不发布完成通知，由外层入口决定重试及最终通知。

当前依赖如下；模板、内置资源和 HTTP 下载本身不依赖外部工具：

| 下载器 | 依赖资源 |
| --- | --- |
| 内置 m3u8、RTSP/RTMP | `ffmpeg` |
| 网站视频 | `yt-dlp`、`ffmpeg` |
| N_m3u8DL-RE | `N_m3u8DL-RE`、`ffmpeg` |
| Telegram | `tdl` |
| gallery-dl | `gallery-dl` |
| aria2 | `aria2c` |

内置 m3u8 在下载分片前解析 ffmpeg，缺少合并工具时提前失败；已有媒体目标且不覆盖时仍跳过依赖解析和下载。

每个平台独立核实上游发布内容，登记：官方项目和许可证、版本或稳定下载地址、系统与架构、包内命令路径、运行库及辅助文件需求。不能从文件名猜测资源存在，也不能把源代码包当作可执行发布包。

- 使用 `Info.Local`、`Info.Remote`、`Info.FullUrl` 和 `Info.Handler` 表达发布包安装规则；确实是通用发布包时才能使用空架构键。没有对应发布包时可通过 `Info.Install` 执行包管理器安装。
- 架构没有对应包且未定义包管理器安装时，在联网下载前报错，不默认改用 amd64；用户已提供可运行的 PATH 程序时仍可使用。
- 裸程序、ZIP、tar.gz 单程序包复用现有安装函数。依赖同包其他文件时必须保留完整运行布局，不能只提取主程序。
- 安装先写临时文件，校验解压及关闭结果、设置执行权限，成功后替换目标；失败保留原安装。相对链接、辅助文件或应用包需要专门处理时，应覆盖升级失败的恢复行为。
- 没有合适的独立发布包时，直接执行已登记的安装命令：macOS 使用 Homebrew，Linux 检测 apt-get、dnf、yum。Linux 非 root 用户通过 sudo 执行，保留当前终端供权限认证；缺少包管理器或安装失败时返回错误，不自动更换安装方式。
- 安装命令和包名由清单固定，使用参数数组执行，不拼接用户输入或自动运行远程脚本。包管理器维护完整依赖，目标目录只创建指向 PATH 程序的链接，支持现有目录、名称及复用规则；覆盖时重新执行安装命令并更新链接。安装后必须确认命令可用，才能继续原下载任务。
- 包管理器继承显式代理设置；空值清除父进程的代理变量。其内部请求不经过任务 HTTP 客户端，不能应用 `proxy.ignore` 正则；系统包管理器自己的仓库、代理和权限策略仍由它管理。包管理器对系统软件的修改及回滚遵循自身行为，CLI 只保证命令链接的替换与失败保留。
- 不支持自动安装的平台仍须保留明确的工具识别和错误提示，不能落入普通仓库下载，尝试一个不存在的资源。

具体工具的支持矩阵以实际核实的发布包为准。发布页可访问或链接返回成功，只能证明地址可用；实际安装和运行需要单独验证。

## 5. 参数映射与输出

| 统一参数 / 行为 | 接入要求 |
| --- | --- |
| `--dir` | 作为输出目录；空值沿用当前目录语义，需要时创建目录 |
| `--name` | 单文件遵循现有名称和后缀规则；多文件作为工具支持的命名模板或目录名时须明确说明，不支持时先报错 |
| `--download` / `upgrade` | 统一表示重新下载并覆盖；不能仍然传递“跳过已有文件”或静默更名参数 |
| `--proxy`、忽略规则 | 代理地址非空时启用、空值时直连；显式 `--proxy=""` 覆盖默认值，子进程不得再次通过环境代理启用代理 |
| `--coroutine` | 仅映射到含义相同的下载并发；标明是每文件连接数、分片并发还是任务并发，并检查上游允许范围 |
| `--retry` | 表示下载单元失败后的额外重试次数；上游使用总尝试次数时换算，不能把 `0` 误传为无限重试 |
| 通知参数 | 由包级下载入口统一处理，适配器不重复发送 |

未适用的通用参数应在帮助和用户文档中说明；用户显式传入且无法兑现的选项必须报错，不能只因存在全局默认值就拒绝任务。不要将所有通用默认值强行映射到每个工具。

代理只保留地址，不另设启用字段或开关。CLI 未传 `--proxy` 时使用全局 `proxy.addr`，未配置时依次读取 `http_proxy`、`HTTP_PROXY`、`https_proxy`、`HTTPS_PROXY`；该默认值在命令层确定，任务执行及依赖安装不得对空值重新补充默认代理。`proxy.ignore` 继续按实际请求地址决定是否绕过代理。

暂不增加任意参数透传。只有出现具体使用需求时才扩展公开选项，并同步定义它与统一参数的优先级。

外部命令通过参数数组执行，不能拼接 shell 字符串。URL、文件路径和代理都作为独立参数；按上游语法防止输入被解释成选项。保留交互终端和原生进度，程序自行输出的日志使用已有脱敏方法，不能打印完整认证参数。

下载结果沿用当前契约：

- 确定的单文件任务返回实际文件路径；只有确认跳过已存在的目标时 `exist=true`。
- 图集、播放列表、磁力/种子等可能产生多个文件的任务返回输出目录；不能把目录已存在当作任务已完成。
- 输出文件扩展名与实际格式一致。原始下载、合并和混流的格式不同，应分别明确，不能仅修改扩展名。
- 覆盖前尽量通过临时文件完成下载。工具不能保证失败保留原文件时，不得对它宣称具有原子覆盖能力，接入时需提供相应保护或说明实际限制。
- 缓存和续传沿用工具本身或现有任务机制，只清理本次任务拥有的临时文件；取消和失败后保留可用进度。

## 6. 失败与退出

保持前台执行，Ctrl+C 能停止当前下载和等待。确有必要的合并收尾沿用已有流媒体行为；不新增后台任务、守护进程或无限等待。

错误必须返回到 handler 和进程退出码，包含工具名称及失败原因。工具运行失败不能继续显示下载完成，也不能自动改用其他工具重新下载。

`MustDownload` 只处理现有可识别的临时网络错误；外部工具自己的重试由参数映射控制。子进程非零退出不等同于临时网络故障，不根据一条模糊日志进入无限重试。明确的认证、权限、参数、格式及架构错误直接停止。

Telegram 保留现有“明确认证错误 → 当前终端登录 → 继续原任务”流程，不把该流程扩散到其他工具的任意错误。

## 7. 验证与文档交付

每个工具的接入至少覆盖实际新增或改变的行为：

1. 匹配与选择：合法输入、伪域名、查询参数、与既有下载器重叠的地址；不兼容参数在依赖安装前失败，已有单文件目标跳过依赖。
2. 参数与结果：含空格路径、命名、覆盖、代理关闭、支持的并发与重试边界、文件或目录返回值。
3. 进程行为：通过测试子进程验证实际参数、非零退出不回退、不误报成功，以及取消后退出。
4. 安装行为：资源与别名、架构映射、不支持架构提前失败；递归顺序、共享依赖复用、别名循环及子任务配置隔离；复用已有通用解压测试，新增特殊安装逻辑再补对应测试。
5. 真实验证：可运行平台实际解包、执行版本或帮助命令，并用受控的小样本完成对应下载；核对文件内容或媒体格式。其他平台的交叉编译、包结构检查与真机运行分别记录。

按影响范围运行相关测试、构建和静态检查。纯文档修改检查链接、措辞和与源码的一致性，无需运行下载或全仓测试。

交付时更新 `i dl` / `i download` 帮助、[用户说明](README.md) 和必要的根 README 示例。说明自动匹配范围、工具获取方式、平台依赖、命名覆盖行为和已验证范围。

删除或替换工具时同步移除其专用参数、资源项、别名、匹配规则、测试和文档；用户已有文件及登录数据不自动删除。

## 9. 当前工具的实现约定

- 三个适配器分别为 `aria2Downloader`、`nm3u8Downloader`、`galleryDownloader`，均实现既有接口，通过 `downloaders` 和 `selectDownloader` 进入统一执行路径。
- 不保留下载器选择字段或选择分支。并发 `0` 表示下载器默认值，重试 `-1` 表示下载器默认值；CLI 未提供参数时传这些值，避免把内置 m3u8 的默认值错误套用到其他工具。
- aria2 只适配磁力和本地种子任务，按原始目录命名，不映射只适用于普通文件的统一参数；HTTP 代理不能转发 BT 对等连接，因此种子入口要求直连。普通 HTTP 文件继续使用内置实现。
- N_m3u8DL-RE 的轨道、混流输出在本任务缓存完成后发布为最终文件，复用缓存锁及权限保留逻辑。N_m3u8DL-RE 统一混流为 MKV，避免把不同格式仅重命名为同一后缀。
- gallery-dl 的 `--name` 表示输出子目录名，不将任意用户字符串拼接为工具命名模板。关闭环境代理，并明确传递跳过或覆盖选项；其输出按文件完成，不提供整批事务。
- `Info.Install` 在没有适用独立发布包时执行系统包管理器安装，阻止安装入口回落到默认资源仓库；PATH 或已有程序仍优先复用。aria2 的 macOS/Linux 入口及 gallery-dl 的 macOS/Linux 非 amd64 入口使用此流程。
- 发布来源及许可证：[aria2 1.37.0](https://github.com/aria2/aria2/releases/tag/release-1.37.0)（GPL-2.0-or-later）；[N_m3u8DL-RE 0.6.0-beta](https://github.com/nilaoda/N_m3u8DL-RE/releases/tag/v0.6.0-beta)（MIT）；[gallery-dl 1.32.18](https://codeberg.org/mikf/gallery-dl/releases/tag/v1.32.18)（GPL-2.0-only）。不将源码包或 Python wheel 当作独立可执行程序安装。
- N_m3u8DL-RE 0.6.0-beta 在本机的输出重定向运行触发 Spectre.Console 异常；真实终端的受控 DASH 自动分流、下载及 MKV 解码已通过。适配层保持原生终端行为和失败退出，不增加 PTY 包装或失败回退；升级上游版本时复查此限制。
